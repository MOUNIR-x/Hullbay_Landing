

# Dépannage et ressources orphelines

Même avec une plateforme robuste comme Hullbay, des situations imprévues peuvent survenir : ressources orphelines après une manipulation manuelle, dérive entre l'état désiré et réel, ou corruption de la base de données. Ce guide vous aide à diagnostiquer et résoudre ces problèmes.

---

## 1. Ressources orphelines et commande Prune

### Qu'est-ce qu'une ressource orpheline ?

Une ressource orpheline est un conteneur, réseau ou volume Docker qui existe dans le cluster mais n'est plus référencé dans la base de données Hullbay. Cela peut arriver si :
- Vous supprimez un projet via `DELETE /api/projects/:id` sans faire `POST /api/projects/:id/destroy` d'abord.
- Vous manipulez Docker directement via la CLI (docker rm, docker network prune).
- Un déploiement échoue partiellement et laisse des artefacts.

### Aperçu des orphelins (mode dry-run)

Avant de supprimer quoi que ce soit, consultez la liste des candidats. Cette route est accessible aux rôles **operator** et **owner**.

```bash
GET /api/prune
```

## 2. Commandes de diagnostic (CLI)

Si vous avez besoin d'investiguer directement sur le serveur, voici les commandes utiles pour comparer l'état réel du cluster avec ce qui est attendu par Hullbay.

### Lister les services et leurs labels

```bash
docker service ls --format "{{.ID}}\t{{.Name}}"
docker service inspect <SERVICE_ID> --format '{{json .Spec.Labels}}'
```

### Inspecter un conteneur spécifique

```bash
docker ps --filter "name=<service_name>"
docker inspect <CONTAINER_ID> --format '{{json .Config.Labels}}'
```

> **Note :** Les labels clefs utilisés par Hullbay incluent `bozando.projectId`, `bozando.nodeName`, `bozando.spec`, et `bozando.system=true` pour les ressources système. Ces labels agissent comme une source de vérité secondaire.
