# Infrastructure et serveurs

Hullbay est conçu pour fonctionner sur un serveur unique ou un cluster Docker Swarm multi-nœuds. Ce guide détaille comment étendre votre infrastructure en ajoutant des serveurs et comment Hullbay sécurise les communications avec le démon Docker.

---

## 🖥️ 1. Architecture du cluster Swarm

Docker Swarm est le moteur d'orchestration sous-jacent de Hullbay. Il permet de répartir les charges de travail sur plusieurs machines physiques ou virtuelles.

### Rôles des nœuds

| Rôle | Description | Recommandation |
| :--- | :--- | :--- |
| **Manager** | Gère l'état du cluster, planifie les tâches, expose l'API Swarm. | 1 à 3 nœuds (impair pour le quorum Raft). |
| **Worker** | Exécute les conteneurs assignés par les managers. | Autant que nécessaire pour la charge. |

:::info Premier serveur = Manager
Lors de l'installation initiale, le premier serveur est automatiquement initialisé comme **Manager** du cluster Swarm. Les serveurs ajoutés ultérieurement sont par défaut des **Workers**, sauf si vous spécifiez explicitement le rôle `manager`.
:::

## 🔌 2. Ajouter un serveur via SSH

Le provisioning de nouveaux serveurs se fait de manière sécurisée via SSH. Hullbay génère une paire de clés éphémère pour chaque opération.

### Procédure

1. Accédez à la section **"Serveurs"** dans le menu latéral (réservé au rôle `owner`).
2. Cliquez sur **"Ajouter un serveur"**.
3. Renseignez les informations :
   - **Nom** : Identifiant lisible (ex: `worker-france-01`)
   - **Hôte** : Adresse IP ou nom de domaine du serveur
   - **Port** : Port SSH (défaut : 22)
   - **Utilisateur** : Utilisateur SSH (défaut : `root`)
   - **Rôle** : `manager` ou `worker`
   - **Credential** : Clé privée SSH ou mot de passe

4. Cliquez sur **"Provisionner"**. La réponse est immédiate (`202 Accepted`) car le provisioning s'exécute en arrière-plan.

### Que se passe-t-il en arrière-plan ?

1. Hullbay génère une paire de clés SSH temporaire (éd25519).
2. Il se connecte au serveur distant via SSH avec les credentials fournis.
3. Il installe Docker si absent, puis joint le cluster Swarm avec le rôle spécifié.
4. La clé privée de l'outil est **chiffrée en AES-256-GCM** et stockée en base de données pour les opérations futures (drain, removal).
5. Les credentials utilisateur (mot de passe ou clé personnelle) sont **immédiatement oubliés** — jamais persistés ni journalisés.

:::warning Sécurité critique
Les clés SSH de l'outil sont chiffrées au repos. Leur perte (si vous perdez `MFA_ENCRYPTION_KEY` dans votre `.env`) rend les serveurs ingérables. **Sauvegardez ce fichier hors du serveur.**
:::

## 🛡️ 3. Le Docker Socket Proxy (Sécurité)

L'une des décisions architecturales les plus importantes de Hullbay est de **ne jamais monter directement le socket Docker** (`/var/run/docker.sock`) dans le conteneur API.

### Pourquoi ?

Monter le socket Docker équivaut à donner un accès **root complet** sur le serveur hôte. Une faille dans l'API ou une injection de commande pourrait compromettre l'ensemble du cluster.

### La solution : Tecnativa Docker Socket Proxy

Hullbay utilise l'image `tecnativa/docker-socket-proxy` comme intermédiaire filtré entre l'API et le socket Docker. Ce proxy expose uniquement les endpoints API Docker nécessaires :

| Endpoint | Autorisé | Usage |
| :--- | :--- | :--- |
| `SERVICES`, `TASKS`, `NODES` | ✅ | Orchestration Swarm |
| `NETWORKS`, `VOLUMES`, `IMAGES` | ✅ | Gestion des ressources |
| `SECRETS` | ✅ | Gestion des secrets Docker |
| `EXEC` | ❌ **BLOQUÉ** | Empêche l'exécution de commandes arbitraires |
| `CONTAINERS` (écritures brutes) | ❌ **BLOQUÉ** | Empêche la manipulation directe de conteneurs |
