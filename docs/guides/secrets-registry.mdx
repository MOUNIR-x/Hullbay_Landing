# Registres Docker et Secrets

La gestion des images privées et des informations sensibles (mots de passe, tokens API) s'effectue via l'interface de Hullbay, garantissant que ces données ne sont jamais exposées dans vos fichiers de configuration locaux ou vos dépôts Git.

---

## 1. Utiliser des Secrets

Les secrets (Docker Secrets) permettent d'injecter de manière sécurisée des données sensibles dans vos conteneurs, sous forme de fichiers temporaires en mémoire.

### Créer un secret

1. Accédez à la section **"Secrets"** (nécessite le rôle `operator` ou `owner`).
2. Cliquez sur **"Nouveau secret"**.
3. Renseignez le nom (ex: `DB_PASSWORD`) et la valeur.

> **Modèle Write-Only** : Une fois créé, la valeur du secret ne peut plus jamais être lue depuis l'interface ou l'API.

### Utiliser un secret dans un projet

Dans votre Canvas (lors de la configuration d'un nœud de type `container`) :
1. Déclarez le secret dans la configuration du nœud.
2. Le secret sera monté dans le conteneur au chemin `/run/secrets/<nom_du_secret>`.
3. Référencez ce fichier dans vos variables d'environnement. Exemple : `POSTGRES_PASSWORD_FILE=/run/secrets/DB_PASSWORD`.

---

## 2. Registres Docker Privés (Registries)

Pour déployer des images stockées sur des registres privés (GitHub Container Registry, Docker Hub privé, GitLab Container Registry), vous devez configurer les identifiants d'accès.

### Ajouter un Registre

1. Allez dans **"Paramètres > Registres"**.
2. Cliquez sur **"Ajouter un registre"**.
3. Renseignez :
   - **URL du registre** (ex: `ghcr.io` ou `registry.gitlab.com`)
   - **Nom d'utilisateur** (ex: `mon-user-github`)
   - **Token ou Mot de passe** (Privilégiez les Personal Access Tokens avec des droits en lecture seule)

Ces identifiants seront utilisés automatiquement par le cluster Swarm (le moteur `dockerode` du backend) lors du `docker service create` ou `docker service update` pour tirer vos images privées avant leur déploiement.
