
# Installation et prérequis

Ce guide décrit comment déployer **Hullbay** sur un serveur VPS ou une machine physique fraîche. L'installation est **idempotente** : vous pouvez relancer le script sans risquer de corrompre une instance existante.

:::warning Prérequis système
- Un utilisateur avec les privilèges sudo (ou accès root)
- Les ports **80** et **443** ouverts (Caddy + Let's Encrypt)
- **Minimum recommandé** : 1 vCPU, 1 Go de RAM
:::

---

## Installation en une ligne de commande

Le moyen le plus simple d'installer Hullbay est le script officiel [install.sh](https://github.com/Fotetsa/hullbay/blob/master/install.sh). Il s'occupe de :

1. Installer **Docker** (via get.docker.com) si absent
2. Initialiser **Docker Swarm** si le nœud n'est pas déjà en mode Swarm
3. Créer le réseau overlay **boz_system** (partagé entre Caddy et les services exposés)
4. Préparer le dossier d'installation (défaut : /opt/hullbay)
5. Télécharger docker-compose.prod.yml et le Caddyfile
6. Générer le fichier **.env** (secrets JWT, MFA, PostgreSQL…) — créé une seule fois, jamais écrasé
7. Démarrer la pile : PostgreSQL, Redis, socket-proxy, API, Web et Caddy

Exécutez la commande suivante en tant que root ou avec **sudo** :

```bash
curl -fsSL https://raw.githubusercontent.com/fotetsa/hullbay/master/install.sh | sudo bash
```

---

## Configuration de l'installation

Le script d'installation initialise le dépôt et les services de base. La configuration de l'instance se fait ensuite dans l'interface d'administration de Hullbay.



---

## Première connexion et bootstrap

Une fois l'installation terminée, le script affiche l'URL d'accès de l'instance.

Dans tous les cas, ouvrez l'URL affichée dans le navigateur pour finaliser la première configuration.

### Créer le compte propriétaire

![Écran de création du premier compte propriétaire Hullbay](/img/screenshots/fr/register.png)

Au premier lancement, Hullbay affiche automatiquement l'écran de **création du premier compte** (Owner). 
l'écran de connexion bascule en **formulaire de création du compte Owner** : remplissez `email`, `password` et `confirm password` puis validez. Une fois le formulaire soumis, le compte Owner est créé et vous serez rediriger vers la page d'activation du MFA.

![Activation de la MFA TOTP pour sécuriser l'accès au panneau Hullbay](/img/screenshots/fr/mfa-activate.png)

:::warning Sécurité
La **MFA (TOTP)** est **obligatoire** pour accéder au panneau. Les comptes doivent activer cette protection avant de pouvoir poursuivre l'accès au panel.
:::

## Services déployés

La pile de production (docker-compose.prod.yml) comprend :

| Service | Rôle |
| :--- | :--- |
| **postgres** | Base de données PostgreSQL 16 (cache opérationnel, audit, canvas) |
| **redis** | Cache et files d'attente |
| **socket-proxy** | Proxy filtré Tecnativa entre l'API et le socket Docker |
| **api** | Backend Fastify — orchestration Swarm, RBAC, secrets, WebSocket |
| **web** | Interface React (canvas visuel, déploiements, monitoring) |
| **caddy** | Reverse proxy, TLS automatique, routage vers l'API et le frontend |

Tous les conteneurs système portent le label bozando.system=true : ils ne peuvent pas être supprimés par les opérations de nettoyage ou de déploiement depuis le canvas.

## Vérifications post-installation

```bash
# Docker et Swarm
docker --version
docker info --format '{{.Swarm.LocalNodeState}}'

# Services de la pile Hullbay
cd /opt/hullbay
docker compose ps

# Réseau overlay système
docker network inspect boz_system
```

Si tous les conteneurs sont running et que l'URL s'ouvre dans le navigateur, passez au guide [Créer votre premier projet](./premier-projet).

## Dépannage rapide

| Problème | Piste de résolution |
| :--- | :--- |
| Script échoue sur Docker Compose | Mettre à jour Docker (Compose v2 requis : docker compose version) |
| Port 80/443 déjà utilisé | Libérer les ports ou arrêter le service conflictuel (nginx, apache2…) |
| HTTPS ne fonctionne pas | Vérifier que le certificat et le port 443 sont bien accessibles depuis le réseau, puis relancer la configuration depuis l'interface |
| .env existant conservé | Normal — le script ne régénère jamais les secrets d'une install existante |

Pour plus de détails, consultez le guide [Dépannage](../guides/depannage).
