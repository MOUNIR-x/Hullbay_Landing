# Chiffrement et gestion des secrets

Hullbay gère deux catégories de secrets distinctes, chacune répondant à un besoin spécifique avec son propre modèle de sécurité :
1. **Les secrets système** (tokens de registre, clés SSH, seeds MFA) : chiffrés en **AES-256-GCM** et stockés en base de données.
2. **Les secrets applicatifs** (mots de passe de base de données, clés API) : gérés via les **Docker Secrets** natifs de Swarm.

---

## 🔐 1. Chiffrement au repos (AES-256-GCM)

### Données chiffrées

Les données sensibles suivantes sont chiffrées avant d'être persistées dans la base de données PostgreSQL :

| Donnée | Colonne Prisma | Usage |
| :--- | :--- | :--- |
| Seed TOTP (MFA) | `User.mfaSecretEnc` | Authentification à deux facteurs |
| Token de registry | `RegistryCredential.tokenEnc` | Pull d'images privées (GHCR, etc.) |
| Clé SSH privée (outil) | `Server.privateKeyEnc` | Provisionnement et gestion des serveurs |

### Algorithme et Clé maîtresse

- **Algorithme** : AES-256-GCM (Galois/Counter Mode). Ce mode fournit non seulement le chiffrement, mais aussi un tag d'authentification garantissant l'intégrité des données.
- **Clé maîtresse** : `MFA_ENCRYPTION_KEY`. Elle est générée lors de l'installation via `openssl rand -hex 32` et stockée dans le fichier `.env`.

:::danger Perte de la clé maîtresse
Si vous perdez `MFA_ENCRYPTION_KEY`, toutes les données chiffrées (MFA, tokens de registry, clés SSH) deviennent mathématiquement indéchiffrables. Vous devrez réinitialiser la MFA de tous les utilisateurs et recréer manuellement les credentials. **Sauvegardez impérativement ce fichier hors du serveur.**
:::

## 🐳 2. Docker Secrets (Swarm)

### Qu'est-ce qu'un Docker Secret ?

Les Docker Secrets sont des données sensibles gérées nativement par le cluster Swarm. Elles sont :
- **Chiffrées au repos** dans le Raft store du cluster (chiffrement mutuel TLS entre les nœuds managers).
- **Montées en fichiers** dans les conteneurs à `/run/secrets/<nom>`.
- **Jamais exposées** dans les variables d'environnement en clair ou dans les labels Docker.

### Le modèle "Write-Only"

Une fois un secret créé via `POST /api/secrets`, **sa valeur n'est jamais retournée par l'API**, même pour un utilisateur avec le rôle `owner`. La route `GET /api/secrets` ne renvoie que les métadonnées :

```json
[
  { "id": "abc123", "name": "DB_PASSWORD" }
